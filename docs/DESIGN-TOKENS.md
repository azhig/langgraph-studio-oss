## Узлы графа

Ключевое наблюдение: **цвета узла не берутся из палитры темы, а задаются инлайн** и образуют
единую схему — из одного базового тона выводятся рамка, фон и текст, и тот же тон получают
исходящие рёбра.

### Схема

| Роль | Как выводится |
|---|---|
| Рамка | базовый тон, непрозрачный |
| Фон | тот же тон с `alpha = 0.1` |
| Текст | осветлённый вариант тона |
| Исходящие рёбра | тон рамки с `alpha = 0.8` |
| Точка-хэндл | заливка тоном рамки, иконка — затемнённым тоном |

### Измеренные значения

**Служебные узлы `__start__` и `__end__`**

```
классы:   border p-2 font-medium rounded-full
радиус:   9999px            (таблетка)
padding:  8px
шрифт:    14px / 500
текст:    #ffffff
фон:      rgba(255,255,255,0.1)
рамка:    1px solid #999999
```

**Обычный узел (`agent`)**

```

радиус:   6px

```

**Узел-инструмент (`action`)**

```

фон:      rgba(158,197,224,0.1)
рамка:    1px solid #64a3ce
радиус:   6px
```

Обратите внимание: радиус обычного узла — **6 px**, а не 8, как казалось по скриншотам.

**Ширина узла** зависит не от ширины текста, а от длины имени: `64 px + 7 px × число символов`
(`__start__` 9 символов → 127, `agent` → 99, `action` → 106, `__end__` → 113, `execute_action` → 162).
Высота всегда 32 px. Ширина задаётся самому узлу React Flow, внутренний блок — `w-full`.

### Цвет узла из имени

Цвет не берётся из палитры и не зависит от «типа» узла (`tools` не голубой «потому что инструмент»):
он детерминированно выводится из имени, поэтому одинаковые имена в разных графах окрашены одинаково.
Правило восстановлено по измерениям одиннадцати узлов (`agent`, `action`, `planner`, `tools`, `research`,
`execute_action`, `summarize`, `tool_node`, `call_model`, `human_review`, `x`) и воспроизводится
в `frontend/src/features/graph/colors.ts` с точностью до единицы RGB:

1. имя → 32-битный хэш вида FNV-1a (умножение в арифметике double, без `Math.imul` — иначе цвета другие);
2. один шаг линейного конгруэнтного генератора (`1664525·h + 1013904223 mod 2³²`);
3. оттенок = дробная часть `(r × 0.618033988749895) × 360°`, насыщенность `50 + r mod 21`,
   светлота `40 + r mod 51` — это базовый тон в HSLA;
4. производные: заливка — тон с alpha 0.1 (0.2 у выделенного); рамка — светлота не выше 60 %;
   текст — светлота 80 % (тёмная тема) / 40 % (светлая); минимапа — светлота не выше 40 % / 60 %;
   рёбра — цвет рамки с alpha 0.8, стрелка — цвет рамки; точка-шестерёнка — рамка (при наведении
   светлота ≤ 45 %) и глиф со светлотой ≤ 25 % (≤ 20 % при наведении); штриховка паузы — текст с alpha 0.15.

Служебные `__start__` / `__end__` получают вместо тона белый (тёмная тема) или чёрный (светлая), и к ним
применяются те же правила: рамка `#999` в тёмной — это белый со светлотой, срезанной до 60 %.
Рёбра и стрелки служебных узлов берут исходный белый/чёрный, а не рамку.

Подписи условных рёбер (`data`): пилюля `rounded-md border px-2 text-sm font-medium` с текстом
светлоты 80/40 %, заливкой alpha 0.2 и рамкой ≤ 60 % тона источника.

### Штриховка при прерываниях

Поверх узла лежит слой `repeating-linear-gradient(45deg, transparent 0 10px, currentColor 10px 20px)`
с `mix-blend-mode: hard-light`, цвет — текст узла с alpha 0.15 (то есть тот же тон, что подпись:
светлота 40 % в светлой теме, 80 % в тёмной). Показывается непрозрачным (`opacity: 1`):
верхняя половина (`top-0 h-1/2 rounded-t-md`) при `Before`, нижняя (`bottom-0 h-1/2 rounded-b-md`)
при `After`, весь узел (`inset-0 rounded-md`) при обоих. Измерено на узле 99×32: слой 97×15,
смещение 1 px сверху (или 16 px при `After`).

Штриховка показывает **включённое прерывание**, а не остановку треда: она появляется сразу
при выборе в меню `Interrupts` и держится, пока пауза не снята. На самой паузе холст не гаснет —
узлы и рёбра остаются в полную силу.

## Раскладка

dagre, `rankdir: TB`, `nodesep: 50`, `ranksep: 50` (это значения по умолчанию dagre), размеры узлов —
как выше. Обратные рёбра (`action → agent`) отдаются dagre как есть: его встроенный шаг cycle removal
разворачивает их сам. Позиции нормализуются к началу координат. Эталонные координаты для графа
`__start__ → agent ⇄ action → __end__`: `(82.75, 0)`, `(96.75, 82)`, `(163, 164)`, `(0, 164)` —
воспроизводятся точно только на dagre 0.8.5 / @dagrejs/dagre 1.1.x.

Вписывание: `fitView` с `maxZoom: 1` — при маленьком графе масштаб 1:1, большой не увеличивается.

## Рёбра

| Тип | Значения |
|---|---|
| Обычное (от `__start__`) | `stroke: rgba(255,255,255,0.8)`, ширина `1px`, без пунктира |
| Обычное (от узла-инструмента) | `stroke: rgba(100,163,206,0.8)` — тон узла-источника |
| Условное | `stroke: rgba(179,91,210,0.8)`, **`stroke-dasharray: 3px 1px`** |

То есть тип линии кодирует условность, а цвет — источник. Подписи условных рёбер по умолчанию не показываются.

Идентификатор ребра в разметке — `<source>-<target>` без порядкового номера (`data-testid="rf__edge-agent-action"`);
номер добавляется только повторной паре с теми же концами.

**Стрелка**: маркер `markerWidth/Height 30`, `markerUnits: strokeWidth`, `orient: auto-start-reverse`,
полилиния `-5,-4 0,0 -5,4 -5,-4` с заливкой цветом рамки источника (без обводки).

**Точки входа и выхода.** Хэндлы React Flow скрыты, точки считаются геометрически: ребро выходит через
нижнюю грань источника (верхнюю, если цель выше) и входит через верхнюю грань цели; точка на грани —
пересечение отрезка между центрами узлов с этой гранью. Поэтому рёбра к соседям слева/справа выходят
не из центра, а со сдвигом к цели (`agent → __end__` начинается в x = 128.7 при центре 146.25).

**Форма.** Одиночное ребро — кубическая кривая React Flow (`getBezierPath`, контрольные точки на
половине вертикального расстояния). Пара встречных рёбер (`agent → action` и `action → agent`) —
две квадратичные дуги с общими концами; контрольная точка сдвинута от середины по x на половину
вертикального расстояния в сторону движения и по y на половину горизонтального против движения,
так дуги расходятся симметрично.

### Важное: тон узла от темы не зависит

Базовый тон один и тот же в обеих темах — `#b35bd2` для обычного узла, `#64a3ce` для
инструментального. Меняются только производные:

| Узел | Тёмная | Светлая |
|---|---|---|
| `agent` — текст | `#daafe9` (осветлённый) | `rgb(130,44,160)` (затемнённый) |
| `action` — текст | `#b1d1e7` | `rgb(49,112,155)` |

То есть достаточно хранить один тон на узел и выводить остальное функцией от темы.

## Прогон: подсветка

Во время выполнения эталон гасит всё, кроме работающего узла. Оболочка узла —
`w-full text-center backdrop-blur-sm transition-all duration-300 ease-in-out`, и к ней
добавляется:

| Состояние | Значения |
|---|---|
| Работающий узел | `opacity: 1`, `transform: scale(1.05)` |
| Остальные узлы | `opacity: 0.1` |
| Все рёбра | `opacity: 0.2` (переход 300 мс) |
| Ошибка или отмена | справа от узла бейдж: `absolute left-full top-1/2 ml-2 -translate-y-1/2`, внутри `rounded-md border border-error bg-error-secondary px-2 py-1` с иконкой `size-2` и текстом `8px/500` |

Анимации CSS у этого нет: значения меняются переходом при смене класса.
Пока идёт прогон, тело карточки `Input` скрывается целиком — остаётся только подвал,
где вместо `Submit` стоит одиночная кнопка `Cancel` (`rounded-md`) со спиннером `size-4 animate-spin`.

### Слайдер детализации

Ползунок в правом верхнем углу (`absolute right-0 top-[80px] w-[120px]`) переключает три вида лога:

| Уровень | Что показано |
|---|---|
| 0 | Сводка хода: метки `Input` и `Output` со значениями, без узлов и времени. Значения рисуются тем же деревом, что и в записи узла: сообщения — карточками «роль + текст», но без пузыря; контейнер `line-clamp-1` |
| 1 (по умолчанию) | Записи узлов; раскрыты ровно две — ввод (`__start__`) и последняя запись хода, остальные свёрнуты независимо от того, что они записали |
| 2 | Те же записи, все раскрыты |

### Ошибки выполнения

Когда узел срывается, эталон не прячет это в консоль: сорвавшийся шаг видно и на холсте,
и в логе, а прогон можно продолжить с того же места.

| Элемент | Значения |
|---|---|
| Бейдж у узла | справа от узла (`absolute left-full top-1/2 ml-2 -translate-y-1/2`), `rounded-md border px-1 py-0.5`, рамка `--border-error`, фон `--bg-error-secondary`, текст `--text-error-secondary` 12px/500 с иконкой |
| Подсветка холста | сорвавшийся узел остаётся ярким, остальные гаснут до 10 %, рёбра — до 20 % (то же состояние, что во время прогона) |
| Плашка в логе | `w-full rounded-sm bg-error py-0.5 pl-1.5 pr-1`; иконка — круг 16 px на `--bg-error-subtle`, цвет `--text-error-tertiary` |
| Текст плашки | 12px/16px: метка `Error` (вес 500, `--text-error-secondary`, в тёмной теме `--text-error-tertiary`) и сообщение (в тёмной — `--text-error-primary`); свёрнуто в одну строку с многоточием |
| Кнопки плашки | `Copy error` и `Show full error message` — `p-0.5 rounded-xs`, иконки 14 px; вторая разворачивает полный текст и поворачивает шеврон |
| Строка продолжения | под плашкой: кнопка `Continue` (`primary`, 13px, `py-1 px-2`, радиус 4), стрелка 16 px `--text-tertiary` и чип следующего узла — `rounded-md border px-2 text-sm font-medium`, цвета из тона узла (фон — тон с alpha 0.2) |

Ошибка разбора формы ввода — другое дело: она остаётся в подвале карточки `Input`
и не попадает в лог.

Сводка хода (нижнее положение слайдера) при незаконченном ходе выглядит так:
контейнер `flex flex-col gap-3 px-7`; вместо значений `Output` — либо `Pending`

## Что осталось домерить

Chat mode (второй режим): карточки диалога снимаются тем же способом при реализации экрана.
Раскрытое дерево значений в логе (не сообщения, а произвольные поля состояния) снято только
по структуре — точные отступы уточняются на этапе E3 вместе с `Pretty` / `JSON`.
