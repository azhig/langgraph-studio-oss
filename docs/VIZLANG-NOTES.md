# Уроки VizLang

[`github.com/vkfolio/Vizlang`](https://github.com/vkfolio/Vizlang) — открытый визуальный отладчик
LangGraph как расширение VS Code (MIT, TypeScript, webview ~3900 строк). Разбиралась ревизия
от 15 июня 2026.

**Код мы не заимствуем.** Этот документ — про задачи, с которыми столкнётся любой, кто рисует
граф LangGraph, и про то, какие из них неочевидны заранее. Реализацию пишем свою.

## Что проект подтверждает

Задача решаема в разумном объёме: весь интерфейс укладывается в ~3900 строк. Выбор стека,
к которому мы пришли независимо (React Flow + dagre + Tailwind + zustand + Vite), у них тот же —
это снимает сомнения, что мы выбрали экзотику.

## Чем его архитектура отличается от нашей

```
VizLang:  VS Code extension ──postMessage──▶ свой загрузчик и исполнитель графа на Python
Наш:      браузер ──HTTP + SSE──▶ Agent Server API
```

VizLang читает граф прямо из исходника и исполняет его сам, минуя Agent Server. Следствие:
у него **нет** тредов, чекпоинтов, ассистентов, форков и перемещения по истории — то есть
всего, что составляет половину нашего списка требований. Опереться на его модель данных
не получится даже концептуально: у нас состояние живёт на сервере и версионируется, у него —
в памяти расширения.

## Инженерные уроки

Задачи, о которых лучше знать заранее.

### Циклы ломают иерархическую раскладку

Для LangGraph `agent ⇄ tools` — норма, а не редкость. Если подать цикл в dagre как есть,
раскладка вырождается.

Это классическая проблема, а не находка VizLang: в алгоритме Сугиямы первый шаг так и называется —
**cycle removal**. Рёбра, замыкающие цикл, временно разворачивают, считают уровни на получившемся
ациклическом графе, затем возвращают исходное направление при отрисовке. Обнаружить такие рёбра
можно обходом в глубину: ребро, ведущее в узел, который уже находится в текущем стеке обхода,
и есть замыкающее.

Нам это нужно решить обязательно — иначе типовой агент выглядит сломанным.

### Ширина узла участвует в расчёте раскладки

Движок раскладки оперирует габаритами, которые ему сообщили. Если объявленная ширина разойдётся
с фактической шириной отрисованного узла, рёбра перестанут попадать в центры. Значит, размер
узла — общая константа для слоя раскладки и слоя отрисовки, а ширина фиксированная, а не
«по содержимому». Кстати, на референсах Studio узлы тоже заметно шире подписей.

### Дробные координаты дают дрожание

Позиции от движка раскладки стоит округлять до целых пикселей — иначе линии «плывут» при зуме.

### Пересчёт раскладки легко зацикливается

Эффект, который читает узлы и записывает узлы, обязан зависеть не от самого массива, а от
чего-то стабильного (количество узлов и рёбер) плюс явного счётчика-триггера для
принудительного пересчёта. Иначе каждая запись перезапускает эффект.

### Параметры, дающие картинку в духе Studio

Направление сверху вниз, интервал между узлами одного уровня ≈60 px, между уровнями ≈80 px,
поля ≈30 px, узел примерно 160×44.

### Состояние узла — это класс, а не инлайн-стиль

Набор состояний, который реально нужен: простаивает, выполняется, завершён, ошибка, прерван.
Оформление через классы позволяет повесить на них анимации (пульсация активного узла, спиннер,
бегущий пунктир на активном ребре) без пересборки React-дерева на каждый кадр.

Палитра VizLang нам всё равно не подходит: у Studio серые служебные узлы, фиолетовый обычный
и голубой инструментальный (см. `references/`).

### Имя узла в событии стрима — это ключ объекта

`stream_mode: "updates"` отдаёт `{"agent": {...}}`, то есть имя узла — ключ. Проверено на живом
сервере, к VizLang отношения не имеет — это формат самого LangGraph.

Для нас важнее другое: у Agent Server есть события `tasks`, дающие вход и выход узла явно,
плюс `checkpoints.next`. Подсветку можно сделать точнее, чем позволяет один только `updates`.

### Разделение состояния по хранилищам

Разумное деление: структура графа и статусы узлов / текущий прогон / диалог / треды.
Первые три к нам применимы; треды и историю проектируем под реальный API с чекпоинтами и ветками.

## Идеи, которые стоит перенять

- **Точки излома рёбер.** Возможность перетащить ребро руками, чтобы развести пересечения.
  В Studio этого нет, а на плотных графах помогает.
- **Экспорт графа в PNG.** Полезно для документации и обсуждений.
- **Переключение направления раскладки** (сверху вниз ↔ слева направо).

## Что это меняет в оценке сроков

Ничего не сокращает: код пишем свой. Экономия — только на ошибках, которые не придётся
совершать самим, прежде всего на раскладке циклических графов.

Основной объём работы там, где у VizLang нет даже прототипа: треды, чекпоинты, форки,
перемещение по истории, ассистенты и прерывания через Agent Server API.
